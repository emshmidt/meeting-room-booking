# Проверка валидации тела запроса

Ручная HTTP-проверка выполнена 17 ноября 2026 года. Для комнат и слотов использовалась Vera, для броней — отдельный запуск от Anna. Результаты ниже основаны на предоставленных HTTP-ответах и наблюдениях в отладчике.

## Результаты HTTP-проверок

| Проверка | Фактический результат |
|---|---|
| Отладчик, `capacity: 0` | `400` со стандартным JSON Spring. Точка останова в POST-методе контроллера не сработала. |
| Отладчик, имя `"  Atlas  "`, вместимость `8`, `hasProjector: false` | Точка останова сработала. `201` с именем `Atlas`, `capacity: 8`, `hasProjector: false`, `description: null`. |
| Комнаты после перезапуска от Vera | Пропуск `hasProjector`, явный `null`, пробельное имя и нулевая вместимость дали `400` со стандартным JSON Spring. Оба контрольных GET вернули те же четыре комнаты, `totalElements=4`. |
| Слот без `endsAt` | `400` со стандартным JSON Spring. Bean Validation отклонила DTO по `@NotNull` до вызова метода контроллера. |
| Слот с `15:00Z` до `15:59Z` | `400` с пустым телом. Обе даты прошли DTO-валидацию, затем `SlotService` отклонил длительность 59 минут. Контроллер преобразовал `InvalidSlotDataException` в `400`. |
| Контроль слотов Orion | До и после обоих отказов GET за `[15:00Z, 16:00Z)` вернул `200`, `items=[]`, `totalElements=0`. |
| Бронь от Anna с `{}` и с `{"slotId":null}` | Оба запроса дали `400` со стандартным JSON Spring. Контрольные GET вернули те же три исходные брони, `totalElements=3`. |

Запросы для повторения сохранены в [rooms.http](../requests/rooms.http), [slots.http](../requests/slots.http) и [bookings.http](../requests/bookings.http).
