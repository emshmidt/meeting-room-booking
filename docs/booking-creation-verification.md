# Проверка создания брони

**Дата проверки:** 13.11.2026. Сценарий выполнен на актуальной сборке в одном процессе с `app.demo-user=anna` на порту 61993. При запуске загружен исходный набор данных. Выбран слот Orion 14 января 2030 года с 10:00 до 11:00 UTC. Его исходная бронь имеет статус CANCELLED.

## Реализованное поведение

- `CreateBookingRequest` принимает обязательный UUID `slotId`. `BookingService` получает пользователя через CurrentUserProvider, слот через TimeSlotRepository и время через Clock.
- Сервис проверяет существование слота, строго будущее начало и отсутствие ACTIVE-брони. Неверные данные, неизвестный слот, начавшийся слот и занятость представлены отдельными исключениями.
- `createBooking` синхронизирован. Чтение занятости, проверка и сохранение выполняются под одним монитором сервиса в пределах процесса. UUID, владелец, ACTIVE и `createdAt` назначаются сервером. Для `createdAt` используется тот же момент, что и для проверки начала слота.
- `BookingResponse` содержит пять полей брони и три поля слота. `BookingController` формирует `201 Created` и `Location` с UUID из тела ответа.

## Результаты HTTP-проверки

Запросы доступны в [bookings.http](../requests/bookings.http). В таблице указано время заголовка `Date`, переведённое в московское время (UTC+3). Все запросы выполнены в указанном порядке.

| Время, Москва | Запрос | HTTP | Фактический результат |
|---|---|---:|---|
| 17:28:48 | GET слотов Orion за `[10:00Z, 11:00Z)` | 200 | `available=true`, `totalElements=1`. |
| 17:28:48 | POST брони от Anna | 201 | Восемь полей, владелец Anna, статус ACTIVE. UUID в Location совпадает с id в теле. |
| 17:28:48 | Повтор POST для того же слота | 409 | Пустое тело. |
| 17:28:48 | GET того же периода после POST | 200 | Тот же слот, `available=false`, `totalElements=1`. |
| 17:28:48 | GET того же периода с `availableOnly=true` | 200 | `items=[]`, `totalElements=0`. |

## Сборка и тесты

`./mvnw package` завершился с `BUILD SUCCESS`. Maven выполнил следующие тесты.

| Набор | Тесты | Падения | Ошибки | Пропуски |
|---|---:|---:|---:|---:|
| com.learning.booking.MeetingRoomBookingApplicationTests | 1 | 0 | 0 | 0 |
| com.learning.booking.service.BookingServiceTest | 1 | 0 | 0 | 0 |
| com.learning.booking.service.RoomServiceTest | 1 | 0 | 0 | 0 |

`BookingServiceTest` использует Clock.fixed и репозитории в памяти. После успешного создания тест проверяет владельца, ACTIVE и `createdAt`. Повторный вызов бросает SlotAlreadyBookedException. Проверка репозитория подтверждает, что осталась одна запись с UUID первой брони.

## Воспроизведение

1. Выполнить `./mvnw package` из корня booking-training.
2. Запустить `java -jar target/meeting-room-booking-0.0.1-SNAPSHOT.jar --app.demo-user=anna`. При выборе другого порта обновить `baseUrl` в HTTP-файле.
3. Выполнить запросы по порядку. Для повторения с доступного слота начать с нового процесса. UUID созданной брони брать из нового ответа.

## Объём проверки

- Последовательный тест покрывает конфликт повторной брони и число сохранённых записей. Защита параллельных вызовов проверена чтением кода синхронизированного метода.
- Ветвь начавшегося слота проверена по исходникам. Граница `startsAt == now` относится к конфликту `409`.
- HTTP-проверка покрывает создание брони, заголовок `Location`, отказы и изменение доступности. Чтение самой брони по адресу из `Location` выходит за рамки текущего набора операций.
- Данные хранятся в памяти одного процесса. Личность выбирается серверной настройкой `app.demo-user`. Предметные ошибки возвращают HTTP-статус с пустым телом.
