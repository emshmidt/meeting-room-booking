# Проверка создания комнат

**Дата проверки:** 12 ноября 2026 года.

## Реализованное поведение

- `CreateRoomRequest` содержит name, Integer capacity, Boolean hasProjector и description. Идентификатор назначается сервером.
- `RoomService` получает RoomRepository и CurrentUserProvider через конструктор. Создание разрешено пользователю с ролью ADMIN.
- До сохранения проверяются обязательность name/capacity/hasProjector, положительная вместимость и непустое имя после удаления краевых пробелов методом strip.
- Сервис создаёт UUID и Room, сохраняет запись и возвращает RoomResponse. Значение false допустимо; null и пустая строка description сохраняют разный смысл.
- `RoomController` принимает JSON через RequestBody и возвращает 201 с RoomResponse. Location для создания комнаты контрактом не требуется.
- `InvalidRoomDataException` обозначает неверные значения полей и преобразуется в 400. `ForbiddenOperationException` преобразуется в 403. Общий IllegalArgumentException не перехватывается обработчиком POST: внутренние ошибки репозитория не классифицируются как неверный ввод.

## Воспроизведение

1. Из корня booking-training собрать актуальные исходники: `./mvnw package`.
2. Запустить `java -jar target/meeting-room-booking-0.0.1-SNAPSHOT.jar --app.demo-user=vera`.
3. Выполнить запросы 1–8 из HTTP-файла по порядку, сохраняя один процесс между созданием Atlas и проверками её состояния.
4. Остановить процесс и запустить тот же JAR с `--app.demo-user=anna`.
5. Выполнить запросы 9–10. Для повторения всего сценария начать с нового процесса и исходных четырёх комнат.

UUID новой комнаты брать из ответа POST. Сохранённый UUID Atlas относится только к зафиксированному запуску. app.demo-user — серверная демонстрационная настройка; личность HTTP-клиента не проверяется.

## Ответственность компонентов

- Request DTO описывает вход, Room — внутреннюю модель, RoomResponse — публичное представление.
- Сервис проверяет роль и значения, нормализует имя и назначает UUID.
- Репозиторий сохраняет готовую модель; контроллер формирует HTTP-ответ.
- Предметные исключения отделяют неверный ввод и запрет операции от внутренних ошибок.

## Текущие ограничения

- Реализованы GET и POST /api/v1/rooms. Операции слотов и бронирования не реализованы.
- POST возвращает 400/403 без тела; GET использует стандартную обработку ошибок. Единый формат code/message/fieldErrors отсутствует.
- Проверки полей создания комнаты выполняются вручную. Полное применение Bean Validation и строгая обработка JSON, включая неизвестные поля и приведение типов, не реализованы.
- Проверки обязательных name/capacity и сохранения description=null подтверждены чтением исходников; отдельные HTTP-результаты этих POST не зафиксированы.
- Данные хранятся в памяти одного процесса и сбрасываются при перезапуске. PostgreSQL не подключена, аутентификация не реализована.
