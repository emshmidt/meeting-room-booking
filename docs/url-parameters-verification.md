# Проверка параметров URL

Проверка выполнена 17 ноября 2026 года на свежей сборке копии проекта. Команда `./mvnw -o clean verify` завершилась с `BUILD SUCCESS`. Все 6 тестов прошли без ошибок и пропусков. Отдельный HTTP-прогон на локальных временных портах подтвердил все 74 контрольных запроса. Использовались исходные данные, запуск от Anna для GET и DELETE и запуск от Vera для POST слотов с валидным телом.

Основные запросы и результаты сохранены в [rooms.http](../requests/rooms.http), [bookings.http](../requests/bookings.http) и [slots.http](../requests/slots.http).

## Пагинация и фильтры

| Проверка | Фактический результат |
|---|---|
| GET комнат, истории и слотов без `page` и `size` | `200`, `page=0`, `size=20`. `totalElements` соответственно 4, 3 и 2. Слоты запрошены для Orion в периоде `[09:00Z, 11:00Z)`. |
| Те же три коллекции с `page=1&size=1` | `200`, одна запись, прежний `totalElements` для каждой коллекции. |
| `page=`, `page=-1`, `page=abc`, `page=2147483648`, `size=`, `size=0`, `size=101`, `size=abc` | Каждый вариант дал `400` со стандартным JSON Spring во всех трёх коллекциях. |
| GET истории с `page=2147483647&size=100` | `200`, пустой `items`, `totalElements=3`. Смещение 214 748 364 700 обработано без переполнения. |
| GET комнат с `minCapacity=8` | `200`, Vega, Sirius и Luna, `totalElements=3`. `minCapacity=`, `0`, `-1` и `abc` дали `400`. |
| GET истории с `status=CANCELLED` и `status=ACTIVE` | `200`, две и одна бронь соответственно. Без `status` — все три брони Anna обоих статусов. `status=`, `active` и `PENDING` дали `400`. |
| GET слотов Orion с `availableOnly` | Без параметра и с `false` вернулись слоты `09:00Z` и `10:00Z`. С `true` вернулся только `10:00Z`. `availableOnly=`, `yes`, `1` и `TRUE` дали `400`. |

Для условных 43 записей при `page=4&size=10` смещение равно 40 и остаются 3 записи. При `page=5&size=10` страница пуста. В обоих случаях `totalElements=43`. Это ручной расчёт на условном наборе.

## Границы периода

| Проверка для Orion | Фактический результат |
|---|---|
| Отсутствует `from` или `to` | `400` со стандартным JSON Spring для каждой границы. |
| `from` или `to` переданы без `Z` или смещения | `400` со стандартным JSON Spring для каждой границы. |
| `from=09:00Z`, `to=12:00+03:00` или `from > to` | `400` с пустым телом после проверки `from < to` в `SlotService`. |
| `[09:00Z, 11:00Z)` и эквивалентный интервал `[12:00+03:00, 14:00+03:00)` | Оба запроса дали `200`. В обоих ответах начала слотов `09:00Z` и `10:00Z`, `totalElements=2`. Слот на верхней границе `11:00Z` исключён. |

В этой таблице время относится к 14 января 2030 года. В HTTP-файле знак `+` в смещении закодирован как `%2B`.

## UUID в пути

| Вариант UUID | GET брони | DELETE брони | GET слотов комнаты | POST слота комнаты |
|---|---:|---:|---:|---:|
| `abc` | 400 | 400 | 400 | 400 |
| `1-1-1-1-1` | 400 | 400 | 400 | 400 |
| `ffffffff-ffff-ffff-ffff-ffffffffffff` | 404 | 404 | 404 | 404 |
| Тот же неизвестный UUID в верхнем регистре | 404 | 404 | 404 | 404 |

Ответы `400` содержали стандартный JSON Spring, ответы `404` имели пустое тело. Контрольное чтение существующей брони Anna с UUID `00000000-0000-0000-0000-000000000001` дало `200` и `ACTIVE`.
